## Predictor

- **architecture**: PatchTST encoder, patch_size=16, → 90 tokens at lookback=1440, with (fable-5-restructuring rework) RevIN-style per-window instance normalization on the input (learnable affine; invariant to the fold MinMax scaler's fixed affine, adapts the encoder input to the current volatility regime instead of fold-global min/max outliers) and volatility-conditioned output scaling (predicted quantiles are multiplied by the window's own per-feature sigma, so interval width tracks current volatility by construction). Epsilon for degenerate flat windows: `PredictorConfig.REVIN_EPS`.
- **output_head**: quantile q10 / q50 / q90 per OHLCV dimension (5 dims × 3 quantiles per future step), **monotone by construction**: the median is predicted directly and the outer quantiles offset from it by softplus increments, so q10 ≤ q50 ≤ q90 holds for every output coordinate — crossing quantiles (which corrupt calibration) are impossible, not merely discouraged by the pinball loss.
- **target**: quantiles of the **cumulative** log-return path from the forecast origin, per OHLCV dimension per horizon step (`PredictorConfig.TARGET_SEMANTICS = "cumulative_logret"`; supersedes per-step log-returns). Rationale: quantiles are not additive — summing per-step q10s does not give the q10 of the 15-minute move, so per-step quantiles could never provide a calibrated interval for the horizon move the trader actually trades; predicting the cumulative path models it directly. Loaders still emit raw per-step targets; `predictor_loss` and the gate-metric collectors cumsum them (single conversion boundary).
- **horizon**: 15 steps direct multi-step. **Autoregressive iteration is banned.**
- **lookback**: TBD via smoke-sweep [240, 720, 1440] before the long training run
- **input_features**: 5 per candle — open log-return, high log-return, low log-return, close log-return, log1p(volume change)
- **vol_logret_floor**: clip `log(volume_t / volume_{t-1})` to `-10.0` (≈ 22,000× volume drop) when `volume_t = 0` or the ratio underflows. Prevents `-inf` from entering the per-fold scaler.
- **vol_t_minus_1_zero_handling**: if `volume_{t-1} = 0`, set `vol_change = 0` (treat as "no information") and emit a structured-log warning. The validator separately surfaces extended zero-volume runs.
- **scaling**: per-fold MinMaxScaler with strict fit-window assertion; rolling features computed sequentially before scaler updates
- **loss**: Pinball (quantile) on the cumulative path + direction penalty, λ ∈ [1.5, 2.0], + coverage penalty (see below). The direction penalty fires on the **final-horizon cumulative close only**: `relu(FEE_THRESHOLD − sign(target_close_cum_H) · q50_close_cum_H)`. Supersedes the per-step form, which compared the per-trade round-trip fee (0.62%) against single 1-minute moves — demanding |q50| ≥ 0.62% *per minute* (~12× the true per-minute median scale) with a gradient that dwarfs pinball's per-element gradient, turning every q50 into a fee-scaled sign flag and destroying median calibration. Confining the penalty to the one (final step, close, q50) coordinate keeps net-of-fee directional pressure on the horizon move (the quantity a trade actually spans) while leaving the rest of the quantile surface honest. Flat market still floors the penalty at FEE_THRESHOLD (trend-loss regression test unchanged).
- **loss_coverage_penalty** (amended 2026-07-01, empirically validated by `scripts/eval_predictor.py` capped bake-off before merge): third loss term `COVERAGE_PENALTY_WEIGHT × Σ_{τ∈{0.10,0.90}} mean_h (smooth_cov_τ,h − τ)²`, where `smooth_cov_τ,h` is the batch mean of `sigmoid((q_τ − y)/s_h)` on the **close** dim and `s_h = COVERAGE_PENALTY_TEMPERATURE_FRAC × std_batch(y_h) + COVERAGE_PENALTY_STD_FLOOR` (width relative to the per-step target std, so sharpness tracks the cumulative path's growing variance). **Width-only by construction**: each tail enters the penalty as `q_τ + (q50.detach() − q50)` — identical value (adds exact zero), but the monotone head's shared median-anchor gradient path cancels, so the penalty can only resize the softplus offsets, never move the median. Computed in fp32 under bf16 autocast (a saturated sigmoid's gradient underflows to zero in bf16 exactly where the penalty must push hardest). Motivation: the capped bake-off (fold 0, 3 seeds, 20 epochs) measured under-coverage on the cumulative model — q90_coverage 0.866 vs 0.90 nominal, calibration_rate 0.747 vs 0.80 — and pinball's marginal calibration pressure (∝ gap, spread over all 45 dim×quantile coordinates) is too weak at capped budgets. Both design guards were forced by measured failures, not theory: without anchor cancellation the tail force drags q50 and collapses DA to a coin flip (~0.49 at weights 1.0 AND 0.1); at temperature_frac 0.1 the smooth indicator's kernel bias (∝ temperature²) mislocates the fixed point and overshoots hard coverage to 0.96. Final values weight=1.0, temperature_frac=0.02 measured on the same fold/seeds: q90_coverage 0.902±0.023, calibration_rate 0.826±0.031 (inside the deploy-gate band), DA 0.529±0.010 and captured fraction 0.256±0.019 held within seed noise, n_used 10,377→14,836. Cost: intervals honestly wider (sharpness 0.0065→0.084) and ~55% slower epochs (14.5→22.5 s at prod batch on the 4060) — accepted; quality is never traded for speed. Close dim only, consistent with `deploy_gates_output_dim` and the direction penalty. Values validated at the 20-epoch capped budget only; re-verify calibration on the first full run.
- **geometry_enforcement**: O/H/L/C consistency (`H ≥ max(O,C)`, `L ≤ min(O,C)`) enforced at every inference step, not only in the rollout sampler — including in any Trader-side mock harness
- **retrain_trigger_conditional**: 7-day NLL or quantile-coverage > 2.0× baseline → manual retrain
- **retrain_trigger_calendar**: 30-day maximum gap regardless of drift metrics
- **retrain_window**: fine-tune on `[t-21, t-7]`, gate on `[t-7, t]` — strictly non-overlapping
- **retrain_warm_start**: from prior checkpoint
- **deploy_gates** (all three required, simultaneously): (a) quantile coverage on locked test set within ±5% of original training-time coverage; (b) Directional Accuracy > 53.5% computed only over predictions where `|q50| > FEE_THRESHOLD`; (c) Calibration rate 75–85%. Under the cumulative `target` convention all three are evaluated in cumulative space (the gate functions are pure same-space comparisons; the collectors cumsum the raw per-step targets) — in particular gate (b)'s fee filter now compares the round-trip fee against the h-step move a trade actually spans, instead of against single 1-minute steps that structurally almost never clear 0.62%.
- **deploy_gates_output_dim**: `close_logret` — all three gates evaluate the Close dimension only. Rationale: execution fills at close-of-candle; Close is the tradeable signal. Consistent with the close-dim direction penalty in the loss and the trader's close-based confidence gate.
- **deploy_gates_quantile_index_pattern**: `PREDICTOR.QUANTILES.index(value)` called once at module scope into private constants (`_Q10`, `_Q50`, `_Q90`). No alias integer constants (`Q10_IDX = 0` etc.) in `constants.py`. The `.index()` call is self-documenting and robust — if the tuple order ever changes, it auto-corrects; a hardcoded `0` would silently break.
- **predictor_checkpoint_dir_and_naming**: weights → `checkpoints/{run_tag}.pt`, scaler → `checkpoints/{run_tag}.scaler.pkl`, where `run_tag = {git_sha}-s{scaler8}-c{constants8}-fold{id}` (the existing `make_run_tag` value). Dir/suffixes in `PredictorConfig.CHECKPOINT_DIR` / `CHECKPOINT_WEIGHTS_SUFFIX` / `CHECKPOINT_SCALER_SUFFIX`. Run-history-preserving (no overwrite) and binds weights↔scaler↔constants by hash. Manifest stays `checkpoints/manifest.json` (deploy default).
- **predictor_checkpoint_save_format**: weights = wrapped dict `{"state_dict" (CPU tensors), "lookback", "constants_sha256", "trained_through_ts_utc", "train_q90_coverage", "target_semantics"}` via `torch.save`, loadable under `weights_only=True`; scaler = `pickle`. `target_semantics` (= `PredictorConfig.TARGET_SEMANTICS`) tags the prediction convention the weights were trained under; `deploy_predictor.py` refuses any checkpoint whose tag is absent or mismatched (a pre-rework per-step model gate-evaluated against cumulative targets would produce silently meaningless metrics), which also retires the old bare-state_dict acceptance path. `deploy_predictor.py` reads both (state_dict via the `"state_dict"` key, scaler via `pickle.load`). `trained_through_ts_utc` is ISO8601 UTC (e.g. `2020-01-05T00:00:00Z`) = last TRAIN candle. Caveat: pickle couples the scaler artifact to the Python version and the `PerFoldMinMaxScaler` class definition — a refactor of either silently breaks `pickle.load`; the SHA256 manifest does not protect against this. Re-train/re-save scalers after any such change.
- **predictor_checkpoint_save_policy**: best-by-`val_total`. `train_one_fold` retains the lowest-`val_total` epoch's weights and restores them into the model before returning; the script persists that (not the last epoch — early stopping leaves ~`EARLY_STOPPING_PATIENCE` epochs of drift past the minimum). `scripts/train_predictor.py --no-save` skips persistence for a pure plumbing smoke.
- **deploy_gate_train_coverage_baseline_split**: validation. The "training-time q90 coverage" baseline for deploy gate (a) is computed on the held-out VAL split (not the in-sample train split), using the best-by-`val_total` weights and the same geometry-enforced, Close-dim `q90_coverage` deploy runs on the locked test set (`evaluate_q90_coverage` in `src/predictor/training.py`). It is embedded in the checkpoint as `train_q90_coverage`. `deploy_predictor.py` reads it (and `trained_through_ts_utc`) from the checkpoint; CLI `--train-coverage`/`--trained-through` are optional overrides, and `--lookback` must equal the embedded lookback or deploy STOPs (architecture-mismatch guard).
- **predictor_prod_batch_size** (user-confirmed 2026-07-01): the real walk-forward run trains at `PredictorConfig.PROD_BATCH_SIZE = 256`, a constant distinct from `SMOKE_BATCH_SIZE = 32`. `PROD_BATCH_SIZE_FALLBACK = 128` exists as a documented **manual** OOM step-down but is **not yet auto-wired** — `src/training_ui/app.py`'s dashboard run calls `train_all_folds` once at `PROD_BATCH_SIZE` with no OOM-retry loop (unlike `scripts/train_predictor.py`'s smoke path, which retries on `SMOKE_BATCH_SIZE_FALLBACK`). This is acceptable because batch 256 peaks at only 474 MB on the 4060's 8 GB (huge headroom, OOM very unlikely); if a future config does OOM, drop `PROD_BATCH_SIZE` to 128 by hand and restart. Background: `SMOKE_BATCH_SIZE` (a 1-epoch/1-fold pre-launch gate value) had leaked into the *real* training run via `src/training_ui/app.py`, leaving the 4060 badly under-fed. Measured on the RTX 4060 (8GB), real data, fold 0, lookback 1440, bf16 AMP: batch 256 = 14.4 s/epoch at 474 MB peak VRAM (vs. 116.6 s/epoch on the pre-optimization batch-32 DataLoader path — an ~8× wall-clock speedup); batch 512 gives no further epoch-time gain (14.3 s/epoch, 840 MB). 256 sits well inside 8GB with wide headroom. This changes optimizer dynamics (larger batch = fewer, lower-variance steps per epoch) but not the loss, model, or windowing. **Flagged per CLAUDE.md "flag every unspecced decision" — the exact production batch size was never in DECISIONS.md; 256/128 chosen from the 4060 benchmark above; user signed off on 256 on 2026-07-01.**
- **predictor_training_perf** (pure engineering; no effect on model quality): the per-fold training data is device-resident. `build_fold_loaders` takes a `device` arg and returns `_WindowLoader` (src/predictor/training.py) instead of a `torch.utils.data.DataLoader`: the whole fold's scaled inputs + raw targets (~3 MB) are moved to the GPU once and each batch is a single vectorised gather over precomputed window offsets — no DataLoader workers, no `pin_memory`, no per-step host→device copy. Windowing semantics are byte-identical to the former `WindowDataset` path (scaled `[i:i+lookback]` input, raw `[i+lookback:i+lookback+horizon]` target, `n = rows−lookback−horizon+1` windows, train `shuffle`+`drop_last`, val full coverage). `train_one_fold` accumulates loss components as on-GPU tensors and only syncs (`.item()`) at logging boundaries. Module-import side effects `torch.set_float32_matmul_precision("high")` (TF32) + `torch.backends.cudnn.benchmark = True` are set once (no-ops on CPU). None of stop/save-event boundaries, best-by-val-total policy, early stopping, grad-clip pre-clip-norm reporting, or the non-finite-loss raise changed.
- **predictor_lr_schedule** (fable-5-restructuring rework): AdamW with linear warmup (`WARMUP_FRAC` of planned steps, now 0.01 ≈ 1 epoch at MAX_EPOCHS=100) then a constant LR that multiplies by `LR_PLATEAU_FACTOR` (0.5) after `LR_PLATEAU_PATIENCE` (3) consecutive non-improving validation epochs. Supersedes warmup-cosine: the cosine annealed over the full `MAX_EPOCHS` (100-epoch) horizon, but the EarlyStopper (patience 10) ends real runs decades of epochs earlier, so training effectively ran at near-peak LR from start to stop and plateaued at a level the LR itself caused. Plateau decay composes with early stopping by construction (its patience is deliberately shorter, so the LR gets ≥2 decay chances to un-stick a plateau before the fold ends).
- **bug_regression_tests** (must pass before training loop ships): variance-floor (`assert loss > 0` for first 100 steps), trend-loss synthetic-input (constant candles → known non-zero output), early-stopping patience exposed in `constants.py`

## Trader

- **architecture**: rules-based for v3. RL deferred until rules-based shows stable signal on validated quantile output (≥3 months paper).
- **inputs**: predictor q10/q50/q90, position state (allocation, unrealized PnL, atr_at_entry), context (atr_normalized, regime, UTC hour sin/cos, day-of-week). **No raw 1440-candle history** — predictor consumed it.
- **position_sizing_base**: fixed-fractional 1% per trade
- **position_sizing_cap**: ±4% hard allocation cap
- **uncertainty_input**: `spread = (q90 - q10) / |q50|` is the explicit input to the confidence gate. Formula is named in `constants.py`, not just in prose. Position size scales from 1% base toward 0 as spread widens.
- **confidence_gate**: if `spread > CONFIDENCE_THRESHOLD` → forced allocation = 0
- **exit_priority_stack** (tier number resolves all conflicts): (1) kill switch → (2) hard stop on net PnL → (3) daily-loss circuit breaker → (4) take-profit → (5) signal reversal ≥3 consecutive candles → (6) trailing stop → (7) time-based
- **stop_loss_evaluation**: net PnL after estimated round-trip fees + slippage. **Identical formula in environment, backtester, and live execution** — implemented once, imported everywhere.
- **predictor_staleness_decay**: linear from full at retrain date to floor (50%) at retrain_date + 30 days; multiplies position size

## Training UI

The payload **schema is unchanged** (`step`/`fold`/`epoch`/`pinball`/`direction`/`total`/`lr`/`grad_norm`) — only the cadence changes; `chart.js addBatch` and the batch-metrics strip render identically. Not display-correctness critical (a 60 Hz browser UI still updates far faster than a human reads).
- **training_ui_data_gate**: on startup, check for `data/raw/XBTUSD_1.csv` (i.e. `DATA.KRAKEN_HISTORY_CSV_NAME`). If absent, training controls (Start/Stop/Save) are disabled and grayed, the header status line reads `Data missing — check KRAKEN_DATA_PATH` in red, and a yellow info box instructs the user to set `KRAKEN_DATA_PATH` (env var, `DATA.KRAKEN_LOCAL_ZIP_ENV_VAR`) to the local Google Drive for Desktop sync path of `Kraken_OHLCVT.zip` and restart the server. **No upload UI** — no drag-and-drop, no `POST /api/setup/upload-data`; data management happens outside the browser and the server must be restarted after the env var is fixed (no hot-reload of the data path).

## Cross-cutting

- **kraken_training_pair**: `XBTUSD` — Kraken's original BTC/USD pair. Inner zip path `master_q4/XBTUSD_1.csv`, extracted to `data/raw/XBTUSD_1.csv`. Data spans 2013-10-07 to 2025-12-31 (244.8 MB, no-header format). `BTCUSD` rejected: only starts 2022-01-01 (2 years), below the 2018-01-01 `historical_start` requirement.
- **historical_start**: 2018-01-01 (covers 2018 bear, 2020 DeFi, 2021 institutional, 2022 FTX, 2023+ ETF era; pre-2017 microstructure rejected)
- **walk_forward_train_val_test**: 150,000 / 50,000 / 10,000 candles
- **walk_forward_stride**: 50,000 (= validation block; non-overlapping validation folds)
- **walk_forward_fold_count**: 78 non-overlapping validation folds against the actual 2018-01-01–2025-12-31 XBTUSD dataset. Recomputed after wiring `HISTORICAL_START` enforcement (`src/data/walk_forward.py::filter_by_historical_start`) into the real-data path — previously unfiltered, so fold 0 silently started training on 2013-10-06 data. `n_total` = 4,207,680 candles (1-minute grid, 2018-01-01T00:00Z through the CSV's last candle 2025-12-31T23:59Z) → `n_usable` = 4,086,720 after the 120,960-candle locked-test carve-out → `floor((n_usable − 210,000) / 50,000) + 1` = 78. Supersedes the prior "~84" estimate, which was never verified against the real CSV's actual date range.
- **locked_test_size**: 120,960 candles (84 days × 1440 = 12 × 1-week non-overlapping windows)
- **holdout_evaluation**: walk-forward inside the holdout: 12 × 1-week windows; gate requires positive Sortino on **median AND worst-week**, regime-stratified positive in trending AND ranging
- **constants_organization**: single `constants.py` at root, organized into `@dataclass(frozen=True)` groups: `PredictorConfig`, `TrainingUIConfig`, `RLConfig`, `TraderConfig`, `ExecutionConfig`, `DataConfig`
- **test_discipline**: tests written and committed before implementation. Verified by `test-enforcer` subagent + git log order.
- **branch_model**: `phase-XY` off `main`; merged to `main` on phase exit (no intermediate `developer` branch)
- **doc_drift_policy**: no separate "correction" documents allowed. `DECISIONS.md` updated in place; amendments → `CHANGELOG.md`. Pre-merge check: any change to a decision value must touch `CHANGELOG.md` in the same commit.
- **hyperparameter_tuning_during_walk_forward**: forbidden during a fold gate evaluation. If a fold fails Sortino threshold, EITHER training continues unchanged OR the model is rejected. No "tweak and rerun." (Bonferroni defense.)
- **search_dev_slice**: an unattended hyperparameter/architecture search loop (`scripts/search_predictor.py`) needs a fast, repeatable train/val slice that carries zero Bonferroni exposure to the real walk-forward gate — i.e. it must never overlap a production fold or the locked test set. `src/data/walk_forward.py::carve_search_slice` takes the most recent `DATA.SEARCH_SLICE_TRAIN` (20,000) + `DATA.SEARCH_SLICE_VAL` (8,000) = 28,000 candles strictly before `HISTORICAL_START`, i.e. from the pre-2018 range this project already excludes from every real fold (`historical_start` above). Verified against the real XBTUSD CSV: 2,227,825 candles fall before the 2018-01-01 cutoff (span 2013-10-06T21:35–2017-12-31T23:59), so the 28,000-candle slice (≈2017-12-12–2017-12-31) uses <1.3% of that range with wide headroom. No test split — the search loop judges candidates on `val_total` only, never against the holdout/permutation gates. This slice is intentionally *not* representative of the 2018+ regime the model is deployed against; it exists purely for fast relative comparison between candidate configs, not for any deploy-gate-relevant metric.
- **search_confirm_seeds**: the search loop's actual noise defense (analogous in spirit to `hyperparameter_tuning_during_walk_forward`'s Bonferroni concern, though it applies to the isolated dev slice, not the real gate). `DataConfig.SEARCH_CONFIRM_SEEDS` = 3. A candidate whose first training seed improves on the current-best `val_total` is provisional only — it is kept solely if a strict majority (`(n+1)//2`) of `SEARCH_CONFIRM_SEEDS` repeat-seed runs (via `train_predictor.py --seed`) also improve on the current best; otherwise the change is reverted as noise. This is the mechanism that gives "kept" its meaning — without it, a single lucky seed could pass a real but spurious improvement through to `constants.py`.
- **search_model_routing**: the search loop's two LLM roles use different models on purpose. PROPOSER = `claude-opus-4-8` (`PROPOSER_MODEL` in `scripts/search_predictor.py`) — it makes bold, higher-blast-radius structural proposals, so it uses the strongest reasoning model. JUDGES (`decisions-auditor` + `leakage-checker`) = `claude-sonnet-5` (`JUDGE_MODEL`) — deliberately NOT co-varied with the proposer, so the compliance gate stays a cheap, fast, independent read-only check rather than moving in lockstep with the thing it audits. Both are pinned explicitly (never the CLI default, which may resolve to an older model). Operational caveat: verify the local `claude` CLI actually accepts `claude-opus-4-8` (`claude -p --model claude-opus-4-8 "ping"`) before a real run — an unrecognized id may error or silently route to a default. Not a `constants.py` value: these are `scripts/`-local model ids, not tunable magic numbers.
- **search_proposal_policy**: each iteration proposes exactly ONE bold, coherent structural move chosen from a fixed menu (`MOVE_MENU` in `scripts/search_predictor.py`: CAPACITY / TOKENIZATION / RECEPTIVE_FIELD / LOSS_SHAPE / SCHEDULE / REGULARIZATION), not an unconstrained free-form edit and not a small multi-field nudge. Rationale: escape local minima with a large but attributable single-lever step that still survives the `search_confirm_seeds` noise defense — when a move is kept you know which structural lever earned it. The `SEARCH_SPACE` hard bounds (per-field ranges/choices) remain freely adjustable working parameters (NOT locked here), except the two bounds fixed elsewhere: `DIRECTION_PENALTY_LAMBDA ∈ [1.5, 2.0]` (loss decision above) and `LOOKBACK ∈ {240, 720, 1440}` (lookback sweep above). `PATCH_SIZE` must evenly divide `LOOKBACK` (PatchTST tokenization); enforced in `validate_candidate`.

## Model benchmark app (cross-phase tooling — `src/benchmark/`)

- **benchmark_app**: a FastAPI + vanilla-JS app (`src/benchmark/app.py`, `static/benchmark/`) that scores every **finished** model (promoted into `PredictorConfig.FINISHED_DIR`, see `benchmark_finished_models_source`) on **simulated net-of-fee trading PnL** and ranks them by **forecast accuracy** (see `benchmark_leaderboard_ranking`). Same stack/process model as the training dashboard (in-process background thread, one job at a time, queue-per-client SSE, `ExecutionConfig.DASHBOARD_BIND_HOST` = 127.0.0.1 only), own port `ExecutionConfig.BENCHMARK_UI_BIND_PORT` = 8002. Supersedes `scripts/eval_predictor.py`'s CLI-comparison role: the `eval` (score a pre-trained checkpoint) and `compare` (side-by-side table) subcommands are **retired**; `eval_predictor.py` keeps only `train-eval` (trains N capped seeds — the one thing the app deliberately does not do). **Flagged unspecced (creative-latitude task):** the app's existence, port 8002, and the design below were chosen this session, not pre-specced in DECISIONS.md. (The ranking key changed from the original `trading.net_return` desc to forecast accuracy — see `benchmark_leaderboard_ranking`.)
- **benchmark_trading_rule** (the fixed measuring instrument): ONE trading rule applied identically to every model — never searched or tuned per model (that would overfit the eval slice; the permutation test guards exactly this garden-of-forking-paths). Rule (`src/benchmark/trading_sim.py::extract_signals`): enter long/short at an origin iff, at the FINAL horizon step of the model's cumulative close forecast, (a) `|q50| > EXECUTION.FEE_THRESHOLD` (predicted move clears the round-trip fee) AND (b) `q10` and `q90` are strictly the same sign (the 80% interval does not straddle zero — a confidence gate that tests whether the calibration/coverage work bought anything tradeable). Hold exactly `PREDICTOR.HORIZON` steps, pay one `FEE_THRESHOLD` round trip, never overlap positions. The rule carries **no constants of its own** — it reads `FEE_THRESHOLD`/`HORIZON` and compares against zero, so there is no second divergent copy of the fee model. Per-fold metrics (net return, per-trade Sharpe, max drawdown, trade count, and TWO hit rates — `directional_hit_rate` = gross right-side share ~0.5 expected, and `hit_rate` = net-of-fee win rate; the "<5%" a reader once saw was the net-of-fee number mislabeled) plus the salvaged captured-fraction/adverse-excursion pair.
- **benchmark_eval_slice**: each per-fold checkpoint (`...-fold{id}`) is scored on **its own walk-forward fold's TEST slice** (`DATA.WALK_FORWARD_TEST` = 10,000 candles, rebuilt via the identical `validate → compute_features → filter_by_historical_start → carve_locked_test → make_folds` path the training run used). This slice is out-of-sample to both training AND the best-by-val-total early-stopping selection (which touches VAL only), so the leaderboard reflects genuine generalization. The **locked test set is never read** by the benchmark — it stays reserved for the deploy gates and the 12×1w holdout evaluator, so the leaderboard cannot burn it. `src/benchmark/engine.py::eval_slice_bounds` places every window's target inside `[test_start, test_end)`, with the `lookback` rows before `test_start` used only as past-context input.
- **benchmark_null_baselines**: every model is read against noise, not just against zero. Two nulls (`src/benchmark/trading_sim.py`): (a) **buy-and-hold** over the same test slice (one round-trip fee); (b) **random-entry at matched trade frequency** — `BenchmarkConfig.NULL_DRAWS` = 200 resamples of the same non-overlapping trade count with random direction on the same realised returns, giving the permutation-style null PnL distribution and an add-one p-value `(1 + #{null ≥ model}) / (draws + 1)` (floor `1/(draws+1)` ≈ 0.005, enough resolution around the pre-live gate's `p < 0.05`). `NULL_SEED` = 0 so a cached benchmark JSON is bit-for-bit reproducible. **Flagged unspecced:** `NULL_DRAWS = 200` and `NULL_SEED = 0` are new magic numbers chosen this session (in `BenchmarkConfig`, not bare); 200 is the cheap-but-sufficient resolution point, not a value from any prior doc. `BenchmarkConfig.NULL_SIGNIFICANCE_LEVEL = 0.05` (display-only: p < this gets "significant" emphasis in the leaderboard) mirrors the pre-live permutation gate's `p < 0.05`; served via `/api/config` so `static/benchmark/app.js` reads it rather than hardcoding a copy (also now serves `TrainingUIConfig.ALERT_AUTO_DISMISS_SECONDS` for the same reason). **Flagged unspecced:** the constant's home is `BenchmarkConfig` for now; revisit if the not-yet-built `scripts/permutation_test.py` needs the identical threshold.
- **benchmark_registry**: renaming a model **never renames the `.pt`/`.scaler.pkl` files** — that would break the weights↔scaler pairing and the SHA256 manifest guarantee. A user-facing "display name" is stored in `checkpoints/benchmark/registry.json` keyed by the immutable run-tag stem (`{git_sha}-s{scaler8}-c{constants8}-fold{id}`); an empty name reverts to the stem. Embedded checkpoint metadata (`lookback`, `trained_through_ts_utc`, `train_q90_coverage`, `target_semantics`, `constants_sha256`) is read `weights_only=True` and mtime-cached in `registry.json` so listing dozens of checkpoints does not re-deserialize their tensors each page load. Per-model results cache to `checkpoints/benchmark/{stem}.benchmark.json` (`BenchmarkConfig.BENCHMARK_DIR`/`REGISTRY_FILENAME`/`RESULT_SUFFIX`); a result file's existence is exactly what makes the UI's "Start benchmark" button disappear. All registry/result JSON is written atomically (tmp + `os.replace`) and strict (NaN → null, since browsers cannot parse bare `NaN`). Checkpoints whose `target_semantics` ≠ `PREDICTOR.TARGET_SEMANTICS`, or missing their scaler/lookback/run-tag, are surfaced as **incompatible** (never silently scored — mirrors `deploy_predictor.py`'s refusal).
- **benchmark_finished_models_source**: the benchmark reads only **finished** models, not every checkpoint in `checkpoints/` (which also holds manual mid-fold saves and search/bake-off scratch). A full walk-forward run that reaches its natural end (no `stop_event`/user stop) COPIES each fold's gate-evaluated checkpoint (weights + scaler) into `PredictorConfig.FINISHED_DIR` = `"checkpoints/finished"` — copy not move, so `CHECKPOINT_DIR` stays the source of truth deploy/manifest read. `train_all_folds` gained a `finished_dir` param and a distinct terminal `state:"completed"` (with a `promoted` count) vs `state:"stopped"` for an aborted run; the training UI passes `REPO_ROOT / FINISHED_DIR`, the benchmark's `create_runner` points its `checkpoint_dir` there. **Flagged unspecced:** the dir name is a chosen default; user chose "auto on full-run completion". Migration: `FINISHED_DIR` starts empty, so the board is blank until a fresh run completes (or a completed run's `{run_tag}.pt`/`.scaler.pkl` are copied in by hand) — no backfill UI was built.
- **benchmark_leaderboard_ranking**: the leaderboard ranks by **forecast accuracy on the out-of-sample fold-test slice**, not by trading PnL. Primary key `statistical.directional_accuracy` desc, tie-broken by `statistical.pinball` asc (the quantile forecaster's own proper scoring rule); missing/non-finite values sort last. Rationale: the predictor forecasts price, so PnL is a fee-dominated downstream proxy — ranking by total net PnL mechanically rewarded whichever model traded LEAST (every trade is negative-EV at fee 0.62% > per-trade edge with DA≈0.5, so total PnL ≈ −trade_count × avg loss). DA/pinball are trade-count-independent, dissolving the volume-vs-quality tension. PnL / edge-vs-null / Sharpe / hit rates remain leaderboard columns (tradeability), they just no longer drive rank; the run-group summary ranks by `mean_da`. **Flagged unspecced:** user delegated the choice ("you pick").
  - **Green "profitable" grade** (2026-07-05; rank basis above is UNCHANGED — the grade is an orthogonal per-row classification, not the sort key): a model is graded `profitable` (green row tint) iff it clears all three gates — (1) **net-of-fee expectancy per trade > 0**, i.e. `trading.net_return / trading.trade_count > 0` (per-trade PnL is a log-return; there is no dollar sizing in the benchmark, so mean net log-return per trade > 0 ⇔ > $0/trade at any positive stake), (2) **statistically distinct from the random-entry null** at `baselines.p_value < BenchmarkConfig.PROFITABLE_P_VALUE_MAX` (= 0.10, `benchmark_null_baselines`' add-one p-value), and (3) **`trading.trade_count >= BenchmarkConfig.PROFITABLE_MIN_TRADES`** (= 30). Below the trade floor — or with a non-finite `net_return`/`p_value` (a model that made no trades has a NaN p-value) — the grade is `insufficient` (dimmed row, neither green nor red): the expectancy estimate is luck-dominated. Otherwise `not_profitable` (red). Three-state string on each `/api/leaderboard` model row (`profitability`); the run-group summary adds `n_profitable`. Computed at **leaderboard read time** by `src/benchmark/trading_sim.py::profitability_grade` from the three persisted result numbers — NOT persisted into `{stem}.benchmark.json` — so threshold changes never invalidate cached results (the cache has no schema-version field). The 0.10 threshold is deliberately **looser** than `NULL_SIGNIFICANCE_LEVEL = 0.05` (which stays the p-cell display-emphasis level, mirroring the pre-live permutation gate): a paper-trading dashboard grade is not a capital-allocation gate. `PROFITABLE_P_VALUE_MAX`/`PROFITABLE_MIN_TRADES` served via `/api/config` (JS reads them, never hardcodes). **Flagged unspecced:** both threshold values user-chosen this session (p < 0.10; ≥ 30 trades).
- **benchmark_analysis_endpoint**: `GET /api/analysis/{stem}` returns ONE JSON joining a model's benchmark result with the training fold record that produced that exact checkpoint, so an AI can read the trading/statistical outcome together with the training-session context and hypothesize why it scored as it did. Join key = the run-tag stem: `FoldRecord` gained `stem: NotRequired[str]` (written by `train_all_folds`'s `fold_complete` payload → the exporter), matched against the benchmark result's stem. `training` is `null` for a checkpoint whose training record predates the `stem` field or was trained outside the UI. `training_metrics.json` stays in `CHECKPOINT_DIR` (not `FINISHED_DIR`); `BenchmarkRunner` gained an injectable `training_metrics_dir` pointing there. No persistent log file / no UI (user chose "JSON endpoint only").
- **benchmark_metric_salvage**: the reviewed economic-metric layer from `scripts/eval_predictor.py` (`target_to_model_space`, `statistical_metrics`, `excursion_metrics` — captured-fraction paired with adverse-excursion, sub-fee moves excluded via `FEE_THRESHOLD`; PR #18 caught a HIGH NaN-poisoning bug there) moved verbatim to `src/benchmark/metrics.py` so the app can consume it without `src/` importing `scripts/`. `eval_predictor.py` imports it back (scripts → src is allowed) and its tests moved to `tests/benchmark/test_metrics.py`. Metric semantics unchanged.

## Pre-training gate (signal-first sanity check)

- **baseline_as_minimum_bar**: best baseline Sharpe becomes the minimum bar PatchTST must clear in walk-forward evaluation
